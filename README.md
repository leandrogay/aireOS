## Mapping Workflow

The upload flow reads and edits mappings through the backend instead of using local fixture data.

A mapping is a rule set, not a copy of a file: one rule per target field, saying
which source column it comes from and what happens on the way. There are two
sources of them, and they are normalised into that one shape for review.

- The deterministic FairPrice mapping lives in [backend/app/services/mapping_service.py](backend/app/services/mapping_service.py). It runs as Python, so it is shown read-only.
- Mappings for new file layouts are generated by Claude in [backend/app/services/generate_mapping.py](backend/app/services/generate_mapping.py) and stored as JSON packets in the bucket under `mappings/pending/` and `mappings/confirmed/`, keyed by a fingerprint of the file's column headers.
- Both are normalised into the review shape by [backend/app/services/mapping_view.py](backend/app/services/mapping_view.py).
- The UI reads and confirms mappings from [frontend/aireos/app/upload/page.js](frontend/aireos/app/upload/page.js) and [frontend/aireos/app/components/upload/MappingReview.jsx](frontend/aireos/app/components/upload/MappingReview.jsx).

| Endpoint | Purpose |
| --- | --- |
| `POST /api/uploads` | Upload files, apply a recognised mapping immediately, or propose a mapping for an unrecognised layout |
| `GET /api/uploads/mappings` | Every mapping the review screen shows, in one shape |
| `GET /api/uploads/mappings/{fingerprint}` | One contract, confirmed if it exists, else pending |
| `POST /api/uploads/mappings/{fingerprint}/confirm` | Approve a proposal, or amend a confirmed mapping |
| `DELETE /api/uploads/mappings/{fingerprint}/pending` | Discard a rejected proposal |

`POST /api/uploads` is the single ingestion entry point. Recognised FairPrice
files use the built-in deterministic transformer. Other recognised layouts use
their confirmed `identity_mapping` and `melt_groups` contract through
`backend/app/services/apply_contract.py`. Unrecognised layouts continue to the
Claude proposal and review workflow. Mapping does not insert rows into BigQuery.

## Coding Standards

The recent changes follow the team conventions in the shared coding standards document.

- JavaScript uses `const` and `let`, arrow functions, strict equality, and async/await.
- Shared logic is split into small helper functions and uses named exports where appropriate.
- Python service code keeps behavior in focused modules with explicit helper functions and targeted tests.
- No existing sales or upload tables are modified; mapping data is written to JSON packets in the bucket, never to BigQuery.
